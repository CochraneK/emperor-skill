# simulation · 模拟场（帝王穿越推演）

把帝王 Skill 当作可运行的行为体，投入历史"处境"中推演其能否处置得当。
模拟场 = **两种容器 × 三种模式 = 6 个格子**。

```
simulation/
├── by-dynasty/     # 容器 A
│   ├── solo/  duel/  coop/
├── one-life/       # 容器 B
│   ├── solo/  duel/  coop/
└── _engine/        # 推演与评分脚本、评分数据
```

## 一、两种容器

### A. `by-dynasty/` —— 每朝单独穿越（单局，不跨代）

- 选定**一个**朝代，帝王在该朝内活动；**结算即结束，不会续到下一个朝代**。
- 每位帝王**开局满血**，不继承前朝结果。
- 用途：干净的横向比较——同一处境下，不同帝王各自怎么处置。

### B. `one-life/` —— 一条命（跨朝连续，苟活）

- 从**唐 / 宋 / 元 / 明 / 清**任一朝代开始，**连续推进**到后续朝代。
- 初始血量 100 HP；每跨一朝，按该朝困局的处置分结算损耗/回复：
  - 处置分 ≥ 体系阈值 → 少量损耗或小幅回升；
  - 处置分偏低 → 重损；**HP ≤ 0 即出局**。
- 用途：看这条命**能推进到哪里**（唐→宋→…→清）。同一帝王在不同起点出发，结果不同。

## 二、三种模式

| 模式 | 目录 | 规则 |
|---|---|---|
| **单人轮值** | `solo/` | 单个帝王独立处置，按评分卡结算。每个帝王"满血"独立计。 |
| **双人对抗** | `duel/` | 任意两帝处于**同一朝代**。**不是各自独立比分，而是相互阻碍竞争**：一方行动会消耗/牵制另一方的资源、兵力、合法性、时间窗口；先达成朝代目标者胜，或被逼入死局者负。 |
| **双人合作** | `coop/` | 任意两帝**协力**处置同一朝代困局，评估「合力 > 各自单干之和」与否（协同增益 / 内耗）。 |

> 三种模式在**两个容器**里都要各跑一遍（`by-dynasty/{solo,duel,coop}`、`one-life/{solo,duel,coop}`）。

## 三、评分与结算

**基础评分卡 v0.2（穿越处置，满分 100）**

| 维度 | 权重 | 判什么 |
|---|---:|---|
| 情境识别 | 25 | 是否抓住该帝困局的核心约束 |
| 模型迁移 | 30 | 能否用**自己的**心智模型对症，而非生搬 |
| 方案可行性 | 30 | 在其框架下该时代能否真落地 |
| 角色保真 | 15 | 全程是否是该帝本尊，不串味 |

判定：**可解 ≥75 ／ 可缓 65–74 ／ 难解 50–64 ／ 死局 <50**。

**模式修正（在基础分之上）**

- `duel`（对抗）：加入**对抗修正** Δ——每回合记录"谁牵制了谁、损耗多少资源/合法性/时间"。胜负看"目标达成"与"是否被逼入死局"，而非直接比基础分。
- `coop`（合作）：加入**协同系数** κ = 双人合力分 ÷（两人单干分之和）² 的几何均值参照。κ > 1 为协同增益，κ < 1 为内耗。

## 四、困局类型（受控词表，9 类）

`创业开国 · 平叛戡乱 · 削藩集权 · 守成休养 · 变法理财 · 开疆边患 · 储位继统 · 权臣党争 · 亡国危局`

> 建类型维度前先套此受控词表，避免细类过碎（曾出现 30+ 细类、每类 1 例、图表无信息量的教训）。

## 六、引擎（`_engine/`）

- `eval_traversal.py` → `eval_score.py` → `eval_report.py`：Skill 质量静态评测三件套。
- `eval_crossing.py` / `eval_crossing_wzt.py`：穿越处置推演 + HTML 报告生成（早期专用版）。
- `eval_crossing_solo.py`：**通用 solo 渲染器**。`--all` 全量重渲 78 份 + 总目录；`--index` 只重建总目录；亦可传 key 单渲。
- `eval_solo_rank.py`：**全库总排名报告生成器** —— 读 `travelers/*.json` 产出 `by-dynasty/solo/solo-ranking.html`（总榜 78 行 / 分档一览 / 9 类困局的 Top5·Bottom5 适配排行 / 结构约束极差对照 / 亡国危局分数带 / 五朝构成）。复用 `eval_crossing_solo` 的 CSS 与判定函数。
- `build_solo_data.py`：从 `eval_crossing.py` 抽取处境全集，生成 `situations.json` / `situations.md`，并迁移旧报告为 `travelers/*.json`。
- `check_solo.py`：**单份结构质检**（条数=77、key 集合=全集减自身、值三元数组、分数 0–100、策/断语 ≤22 字、`dyn` 合法）。`--strict` 有问题即退出码 1。
- `cross_check_solo.py`：**全库交叉检验**（亡国危局越界、四档跨人极差、均分分布、「朕」使用率、类型难度排行）。
- `normalize_rows.py`：把历史遗留的 `{plan,score,note}` 写法归一为 `[策,分,断语]`（`--apply` 才写盘）。
- `reign_order.json`：**78 帝即位年表**（`{key: [year, seq]}` + 各朝起讫）。报告与总目录的「按时间顺序」呈现即以此为排序依据。
- `reversal.py`：翻盘三条件效度检验聚合与报告生成（读 `reversal_part*.json` + `reversal_t1_part*.json`）。
- `SOLO_TASK_BRIEF.md`：分派给 worker 的统一任务简报（评分口径、校准锚、硬约束、输出格式）。
- 配套 `*.json` 为指标与评分数据；`travelers/<key>.json` 为 78 帝各 77 条处置。运行需本机 Python 3.13（脚本内路径以本仓库为准）。

## 八、效度检验：翻盘三条件（`validity/`）

评分卡的问题在于它没有把**处境有多难**和**人能不能改变处境**分开。为此引入一组独立于结局的前置结构变量：

> **① 手中有兵（中央仍控一支忠于自己的武力）　② 库中有粮（至少一处截不断的税源）　③ 敌未整合（外部对手仍互相牵制）**
> 三条全中→有救；中两条→只可延祚；中零至一条→死局。

对 15 处「亡国危局」在**两个时点**各点验一次：**T0 = 帝王即位之时**，**T1 = 处境题面所述的危局爆发之时**。

判定细则（两轮一致，仅换时点）：军队存在但指挥权已归宦官／权臣／藩镇／外敌者 b1 判假；财赋区已陷战乱或被截留者 b2 判假；对手已整合为单一强权者 b3 判假。

**用法**：`python reversal.py` → 重新生成 `validity/reversal-validity-report.html`。

## 九、全库交叉检验（78 帝 × 77 处境）

`python check_solo.py` 验单份结构，`python cross_check_solo.py` 验全库统计。当前实测（2026-09-13）：

**A. 亡国危局档 —— 硬约束成立**

78 位全部落在 **39.0–51.3**（极差 12.3、标准差 2.74），**零越界**。最高普仪 51.3、最低宋理宗 39.0。

**B. 四档跨人极差 —— 人定胜负成立**

| 类型 | 全库均分 | 跨人极差 | 最低人 | 最高人 |
|---|---:|---:|---|---|
| 守成休养 | 69.6 | **35.6** | 唐哀帝 47 | 宋真宗 82 |
| 变法理财 | 61.2 | **34.2** | 唐哀帝 43 | 宋神宗 77 |
| 权臣党争 | 59.8 | **25.6** | 宋徽宗 49 | 宋哲宗 74 |
| 储位继统 | 62.5 | **25.0** | 唐中宗 51 | 清德宗 76 |
| 亡国危局 | 45.1 | 12.3 | 宋理宗 39 | 溥仪 51 |

四档极差是亡国档的 **2.0–2.9 倍**，与「分差须由工具箱解释、亡国属结构性困局」的设计预期一致。

**C. 均分分布**：均值 59.0、极差 18.4、标准差 4.21；64/78 落在 55–72 主体带，14 位偏低者全部是幼主／傀儡／在位极短（唐哀帝、宋徽宗、唐中宗、唐顺宗、宋度宗、宋末三帝、明光宗等），**无人偏高越 72**。

**D. 断语口吻**：全库「朕」字出现率 75.6%（4540/6006）。未出现者多为省略主语的自省句（「公主干政，亦当以祖宗法度治之」），口径仍属本人，未出现通用评语，按软指标记录。

**E. 类型难度排行（全库均值，越高越易）**

```
守成休养 69.5 ｜ 平叛戡乱 67.3 ｜ 削藩集权 64.3 ｜ 储位继统 62.4 ｜ 创业开国 61.5
变法理财 61.0 ｜ 权臣党争 59.9 ｜ 开疆边患 58.6 ｜ 亡国危局 45.1
```

与李世民单体基线的排序大体同构（削藩/平叛居前、亡国垫底），**但「创业开国」由单体第 1 名（78.3）降到全库第 5 名（61.5）** —— 全库含 20 余位幼主与守成之君，他们面对「创业开国」几乎无策（可解 ≤5 条），把这一类拉平。这正说明**类型均分是「处境难度 × 穿越者构成」的混合量，不能当纯难度读**。

> 78 帝中 `lishimin` / `wuzetian` 两份为早期迁移，`liyuan` 亦属旧版；其「策 / 断语」原为长文案，2026-09-13 已由专项分包压缩至 ≤22 字以统一规格，**分数与判断未改动**。原始长文案的判据见 `validity/reversal-validity-report.html`。
